## Symptoms

**Expected:** On `main`, the blocking `test-suite` matrix (ubuntu / macos / windows) passes, and the non-blocking `quality-checks` job passes.

**Actual:** On run `37759669726` (and the preceding four runs), the CI result is `failure`:
- `Test Suite (macos-latest)` → step `Run Tests` fails (BLOCKING).
- `Quality Checks` → step `Run Pre-commit Hooks` fails (non-blocking, `continue-on-error: true`).
- `Test Suite (ubuntu-latest)` and `Test Suite (windows-latest)` pass.

The macOS failure is NOT a logic failure in any test. The blocking `Run Tests` step reports:
```
1670 passed, 8 skipped, 3 errors in 23.57s
```
The three "errors" are all the SAME assertion firing at session teardown of three xdist workers, raised by the Poka-Yoke fixture `_assert_no_test_pollution` at `tests/conftest.py:209`:
```
Failed: Test suite left filesystem pollution!
Before: 0 entries
After: 1 entries
New/Modified/Untracked files:
?? docs/templates/
```
So the suite leaves an untracked `docs/templates/` directory in the REPO ROOT.

**Minimal reproduction:**
1. `gh run view 37759669726 --log-failed` → observe the `?? docs/templates/` pollution assertion.
2. Locally (macOS): run `uv run pytest` and check `git status --porcelain` for `?? docs/templates/`.

## Diagnostic Analysis

### Causal Model
The `templates-and-init` slice (03-03) added auto-scaffolding of `docs/templates/` on bare `teddy init` (via `InitService.ensure_templates_initialized`). The session-scoped autouse fixture `_assert_no_test_pollution` (`tests/conftest.py:209`) snapshots `git status --porcelain` before the suite and diffs after. Some test path invokes the real init/scaffold against the REAL repo root instead of an isolated `tempfile.mkdtemp()` workspace, leaving untracked `docs/templates/` behind. The fixture then fails at teardown of whichever xdist worker(s) executed the polluting test (3 workers reported). Because the fixture only fires when the before/after snapshots differ, and xdist distribution + per-worker ordering vary by runner, the pollution is detected only on some runner orderings — explaining the macOS-only CI symptom while ubuntu/windows happened not to trip it.

UPDATE (Turn 10): the write-target mechanism is resolved at the code level. `InitService._init_templates(dest_dir="docs/templates")` → `_copy_bundled_files` → `IFileSystemManager.create_directory("docs/templates")` → `LocalFileSystemAdapter._resolve_path("docs/templates")`, which JOINS the relative path onto the adapter's injected `root_dir` (base = `os.path.realpath(root_dir)`, computed lazily) and calls `.mkdir(parents=True, exist_ok=True)`. The relative path is resolved against the adapter's `root_dir`, NOT the raw process CWD. A polluting call is therefore one whose filesystem adapter was CONSTRUCTED with a `root_dir` that resolves to the REPO ROOT (e.g. `root_dir="."` evaluated while CWD is the repo root, or `find_project_root()` / `Path.cwd()` returning the repo root).

UPDATE (Turn 6): the full-suite MRE ran `uv run pytest` locally with a clean `docs/templates` baseline and produced `1673 passed, 5 skipped`, leaving `docs/templates` ABSENT — the pollution did NOT reproduce locally under the default `-n auto` worker count.

UPDATE (Turn 8): REPRODUCED. Running `CI=true uv run pytest -q -n 3 -rs` produced `1673 passed, 5 skipped, 3 errors` with `docs/templates/` PRESENT at the repo root (the Poka-Yoke fixture fired at teardown of all three workers). The trigger is therefore the xdist WORKER COUNT (3), not the OS: local `-n auto` (many cores) passed, `-n 3` pollutes, and GitHub `macos-latest` gets ~3 cores (the 3 teardown errors equal its worker count) while ubuntu/windows get more. Mechanism: `__main__._ensure_project_initialized` → `InitService.ensure_initialized` → `_init_templates(dest_dir="docs/templates")` writes to the RELATIVE path resolved against the process CWD; some test triggers this path while its CWD is the real repo root. The regressing delta made previously-hidden pollution visible — before it, the same path wrote only `.teddy/` (git-ignored), so the fixture never tripped.

UPDATE (Turn 11): the polluting CALL SITE is the bare-`init` CLI path. `__main__.init_callback` calls `_ensure_project_initialized(container, root_dir=str(Path.cwd()))`, and when no subcommand is given it THEN unconditionally executes `container.resolve(IInitUseCase).ensure_initialized()`. Because that second call runs regardless of whether `_ensure_project_initialized` was patched, a test that invokes the bare `init` command still exercises the real `InitService.ensure_initialized()`, which writes `.teddy/` (git-ignored) AND `docs/templates/` (NOT git-ignored). The per-test autouse fixture `clean_test_env` resets CWD to `find_project_root()` — the repo root — after every test, so a bare-`init` test that does not chdir into an isolated workspace writes `docs/templates/` straight into the repo root. The xdist-robust probe (`spikes/debug/probe_pollution_file.py`) flagged three tests, one per worker; since `docs/templates` is a SINGLE shared directory, only the FIRST worker to create it is the true polluter — the first log line names `tests/suites/unit/adapters/inbound/test_cli_helpers.py::test_init_command_calls_prewarm_imports`; the other two flags (`test_resolve_setup_editor_decision_table[...]`, `test_get_completion_wraps_errors_in_llm_api_error`) are false positives that merely observed the shared directory appear mid-test.

UPDATE (Turn 12): the polluter is CONFIRMED as a pure TEST-ISOLATION defect, not a production bug. Running each candidate in isolation showed `test_cli_helpers.py::test_init_command_calls_prewarm_imports` => `POLLUTED(docs/templates)`, the whole `test_cli_helpers.py` file => `POLLUTED`, and both false positives => `clean`. That test invokes `runner.invoke(app, ["init"])` while patching ONLY `__main__._ensure_project_initialized` to a no-op; because `init_callback` STILL calls `container.resolve(IInitUseCase).ensure_initialized()` directly for the bare `init`, the real scaffold runs against the container's DEFAULT `IFileSystemManager` (`LocalFileSystemAdapter(root_dir=".")`, whose `_resolve_path` lazily computes `realpath(".")` = the process CWD). With no `chdir` into an isolated workspace, the write targets the repo root. The production code path (`_ensure_project_initialized(container, root_dir=str(Path.cwd()))`) is CORRECT; the delta in 03-03 merely made a pre-existing latent isolation defect observable by adding a non-git-ignored artifact (`docs/templates/`) alongside the previously-invisible `.teddy/`.

UPDATE (Turn 14): the FIX is VERIFIED (Zero-Touch / Shadow File). The minimal, test-intent-preserving remedy is to run the polluting test inside an isolated workspace by adding `monkeypatch.chdir(tmp_path)` to `test_init_command_calls_prewarm_imports`. Because the default `IFileSystemManager` is a transient `LocalFileSystemAdapter(root_dir=".")` whose `_resolve_path` lazily computes `realpath(".")` at call time, changing CWD before `runner.invoke(app, ["init"])` redirects BOTH the `.teddy/` and `docs/templates/` scaffolding into `tmp_path`, leaving the repo root clean while the test still asserts `prewarm_imports()` is called exactly once. A Shadow File copy (`spikes/debug/shadow_test_cli_helpers.py`) carrying exactly this one-line change ran `4 passed` and left `docs/templates` ABSENT at the repo root. This is a TEST-ISOLATION defect only — `src/` is unchanged and production behavior is unaffected.

UPDATE (Turn 18): the serial-vs-parallel discrepancy is RESOLVED via state coupling on the process-global DI container. The polluter resolves `IFileSystemManager` from `teddy_executor.container._container` (it does not request the `container` fixture, so it never gets a fresh container; and its `_ensure_project_initialized` no-op patch skips the re-registration that would set an isolated root). Two regimes exist: (1) DEFAULT root intact (`root_dir="."`) → `_resolve_path` computes `realpath(".")` = the repo root → pollution (experiments A, B, D); (2) a preceding real-`init` test (e.g. `test_init_cli_regression.py`, which `chdir`s into a `TemporaryDirectory` and runs the UNPATCHED `init`) re-registers `IFileSystemManager` with an absolute temp `root_dir` that PERSISTS on the global container → the polluter's writes land in the leaked temp root, NOT the repo root → no pollution (experiment C, probe `fs_root=<tmp>`). This is why the full SERIAL suite (`-n 0`, Turn 17) stayed clean while the `-n 3` CI-shaped run pollutes deterministically: in serial, a leaky test precedes the polluter in the single shared process; under xdist, the polluter lands in a worker whose global container still carries the default root. The `monkeypatch.chdir(tmp_path)` fix is robust to both regimes, and the leak merely changes WHICH disposable root receives the writes.

### Discrepancies
- The pollution is `docs/templates/` only, and it is intermittent across OS matrix runners (macOS fails, ubuntu/windows pass on the SAME commit). (Resolved: NOT OS-specificity — it is an xdist worker-COUNT/ordering artifact. The polluter `test_init_command_calls_prewarm_imports` unconditionally runs the real `ensure_initialized()`, so whether the shared `docs/templates/` directory is still present at each worker's session-scoped teardown snapshot depends on the worker count and test distribution; macOS `-n 3` reproduced it deterministically while ubuntu/windows with more cores happened not to surface it on the same commit.)
- Local full-suite reproduction FAILED: `uv run pytest` (macOS, xdist, `-n auto`) left `docs/templates` absent (`1673 passed, 5 skipped`), yet CI macOS consistently reports `1670 passed, 8 skipped, 3 errors`. (Resolved: not a platform difference but a worker-COUNT difference — `CI=true uv run pytest -n 3` reproduces the pollution and the 3 errors locally, matching macos-latest's ~3-core worker count. The residual 3-test passed→skipped delta (1670 vs 1673) is a separate, likely platform-skip artifact and does not gate the root cause.)
- Second negative local reproduction: the targeted init/template/auto-init acceptance subset ran clean (4 passed) with `docs/templates` absent, and `docs/templates` is NOT git-ignored (`git check-ignore` → not ignored). (Resolved: those four tests are individually isolated; the polluter only appears under the full-suite `-n 3` ordering, confirming a cross-test/ordering trigger rather than a self-contained bug in any single init test.)
- Full SERIAL suite (`uv run pytest -n 0`) produced NO pollution and NO `[POLLUTER]` line (Turn 17), contradicting the model that the polluter ALWAYS writes to the repo root. (Resolved: state coupling via the process-global DI container. The polluter resolves `IFileSystemManager` from `teddy_executor.container._container`; a preceding real-`init` test leaks an absolute temp `root_dir` onto that global container, redirecting the polluter's writes away from the repo root. Serial ordering surfaces the leak (masking pollution); the `-n 3` xdist distribution places the polluter in a worker whose container still has the default `root_dir='.'`. Confirmed by experiment C: probe reported `fs_root=<tmp>` when a leaky test ran first.)

## Solution

**Root cause (verified):** A pre-existing TEST-ISOLATION defect in `tests/suites/unit/adapters/inbound/test_cli_helpers.py::test_init_command_calls_prewarm_imports`. The test invokes the real bare-`init` CLI (`runner.invoke(app, ["init"])`) while patching only `__main__._ensure_project_initialized` to a no-op — but `__main__.init_callback` UNCONDITIONALLY calls `container.resolve(IInitUseCase).ensure_initialized()` for a bare `init`, which the no-op patch does not intercept. That call scaffolds `.teddy/` (git-ignored) and — since slice 03-03 — `docs/templates/` (NOT git-ignored) into the container's DEFAULT `IFileSystemManager` root (`LocalFileSystemAdapter(root_dir=".")`, resolved lazily to the process CWD). Because the test never changed CWD, the write landed in the repo root, and the session-scoped `_assert_no_test_pollution` Poka-Yoke correctly flagged the untracked `docs/templates/`. The symptom surfaced only on the 3-worker `macos-latest` matrix (worker-count/ordering dependent), which is why ubuntu/windows appeared green on the same commit.

**Fix (verified via Shadow File):** Add `monkeypatch.chdir(tmp_path)` to the polluting test so the real `ensure_initialized()` writes stay inside a disposable workspace. No production code change.

**Systemic prevention (finalized):** The systemic audit confirmed the defect is CONTAINED to the single polluter — no other non-harness test invokes a side-effecting CLI command without CWD isolation (the acceptance layer's `CliTestAdapter` isolates via `m.chdir(target_cwd)`; integration raw invokers isolate via `chdir` and/or the mocked `container` fixture; the two other bare-`init` tests already `chdir`). No production (`src/`) change and no broader refactor is required. Prevention therefore rests on two existing mechanisms plus one optional hardening: (1) the session-scoped `_assert_no_test_pollution` Poka-Yoke already fails the suite if any test writes to the repo root — it correctly caught this bug; (2) the `clean_test_env` autouse fixture resets CWD between tests; (3) OPTIONAL future hardening (deferred; not required once the sole polluter is isolated): a shared harness helper that auto-isolates CWD for raw unit-level `runner.invoke(...)` calls, mirroring `CliTestAdapter`.
