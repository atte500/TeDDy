# Bug: trafilatura logs "discarding data: None" warning during web scraping
- **Status:** Unresolved
- **Milestone:** N/A
- **Vertical Slice:** N/A
- **Specs:** N/A

## Symptoms
During a Pathfinder session that performs web searches and scraping, the log message "discarding data: None" appears in the terminal output. This is a WARNING-level log from trafilatura that indicates it's discarding content because the `source` parameter is `None` or empty. The user does not want this log to appear — either the data should not be discarded, or the log should be suppressed.

## Context & Scope
### Regressing Delta
Not a regression — this behavior has existed since the web scraper adapter started using trafilatura. The log is generated by trafilatura's `bare_extraction()` whenever it catches a `ValueError` or `TypeError` during extraction, and the `source` field on the `Extractor` object is `None` because our adapter never passes the `url` parameter to `trafilatura.extract()`.

### Environmental Triggers
`trafilatura.extract()` is called from `WebScraperAdapter._get_content_impl()` (line 348 in web_scraper_adapter.py) without the `url` parameter. The warning is triggered when extraction fails for any reason (empty/invalid HTML, output too short, duplicate detection, language mismatch) and trafilatura's `except (TypeError, ValueError)` block logs `options.source` which is `None`.

### Ruled Out
- `WebSearcherAdapter.search()` — wraps with `logging.disable(logging.CRITICAL)` and has no direct trafilatura calls
- `cli_helpers.py` — only imports trafilatura for a `# noqa: F401` lazy import check
- The `logging.disable(logging.CRITICAL)` wrapper in both adapters should suppress the WARNING, but the user reported seeing it anyway — either the suppression is not 100% reliable, or the observed output was from an older version before suppression was added (Case File #39)
- No race condition or threading issue (single-threaded session workflow)

## Diagnostic Analysis
### Causal Model
1. `WebScraperAdapter.get_content()` calls `_get_content_impl(url)` inside a `logging.disable(logging.CRITICAL) / finally: logging.disable(logging.NOTSET)` wrapper
2. `_get_content_impl()` fetches HTML via `_fetch_with_rotation()`, then calls `self._get_trafilatura().extract(html_content, output_format="markdown", ...)` — **without passing the `url` parameter**
3. Inside `trafilatura.extract()`, `bare_extraction()` creates an `Extractor` object: `Extractor(url=None, source=None, ...)`
4. `Extractor.__init__()` calls `_set_source(url=None, source=None)` → `source = url or source = None` → `self.source = None`
5. If extraction fails (empty HTML, content too short, language mismatch, size check, dedup detection), a `ValueError` is raised
6. The `except (TypeError, ValueError)` block logs `LOGGER.warning("discarding data: %s", options.source)` → output is `"discarding data: None"` because `options.source` is `None`
7. The `logging.disable(logging.CRITICAL)` wrapper SHOULD suppress this `WARNING`-level message, but the user observed it, suggesting either: (a) the session was from an older codebase version before the suppression was added, or (b) `logging.disable()` has a subtle failure mode (e.g., if trafilatura's logger was configured before the disable call took effect in the handler propagation chain)
