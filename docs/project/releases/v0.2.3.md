# TeDDy v0.2.3

## Features:
- **Per-persona model routing:** an `agents` block in `.teddy/config.yaml` routes one persona to its own model while `llm.*` stays the shared default. The effective model resolves from the `--model` flag first, then `agents.<persona>.model`, then `llm.model`, and every key a persona omits falls back to the global `llm` block. `--model` replaces only the `model` key, so a persona-level `api_key` or `api_base` still applies, and the merge is one level deep, so a mapping-valued key such as `extra_headers` replaces the global value wholesale rather than merging key by key. An empty or whitespace-only persona model falls back to `llm.model`, persona names match case-insensitively, and the effective model is what the startup banner and the turn metadata record. `teddy init config` ships an `agents` block that lists every persona with its settings commented out.
- **Configurable update source:** the new `update.index_url` setting points the update check at a fork's index or a static `version.json` instead of always reading official PyPI, and an empty value keeps the official endpoint. The source only has to be PyPI-JSON-shaped, carrying `{"info": {"version": "x.y.z"}}`. The README documents this alongside installing from a fork or a private index.
- **Formatted message bodies on the terminal:** a communicating turn's Message body renders as formatted prose, with Markdown markers consumed and fenced blocks visually delimited, in the interactive ask header as well as in the pipeline printer and the `resume -p` reprint. A non-terminal stdout still receives the raw Markdown, so piped and redirected output stays byte-identical. This adds `rich` as a runtime dependency.
- **Interrupted turns recover on resume:** a turn that began executing but never finalized, such as one killed mid-run, is closed with an `INTERRUPTED` report on `teddy resume` instead of replaying its abandoned plan, and the successor turn is planned from scratch against the observed workspace. `teddy resume -m` records the reply as the interrupted report's `## User Request`. A message-only pending turn keeps its re-dispatch, and a turn that never dispatched keeps its in-place `-m` completion.
- **Four-section rationale:** the plan rationale contract is now exactly four `###` sections: `Summary`, `Expectation`, `Progress`, and `Notes`. Any other heading or numbered marker, such as `1. Section`, is body text and merges into the preceding section. A rationale that carries none of the four headings, such as one written against the previous format, still renders in full: the plan reviewer shows its whole content as a single `Raw` node styled quieter than the protocol sections instead of dropping it, so stored plans and resumed sessions stay reviewable. The rationale is read as plain text everywhere else, so nothing depends on the section shape; `teddy init prompts` refreshes customized prompts to the new section names.
- **Tooling and CI:** a deterministic AST check now rejects a core import of the adapters, the registries, the DI container, or an adapter library such as `litellm`, `typer`, or `textual`, and rejects `spikes/` code reaching `src/` or `tests/`. It runs as its own structural CI step and as a manual-stage pre-commit hook. The coverage gate is retired, dropping `pytest-cov` and the coverage configuration from the dev dependencies.

## Fixes:
- **Session-scoped context:** the context partition and the TUI grouping now gate on the session root being rendered, so a file read from another session appears under `## Resource Contents` instead of posing as the current session's own history.
- **Missing initial message:** closing the opening prompt now prints a yellow `Session not started (no initial message).` notice and exits, instead of an `Error:` line.
- **`teddy init` status wording:** change counts read `1 file` or `N files` instead of `file(s)`.
