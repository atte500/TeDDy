# Slice: Context-Aware `e` Actions in the Reviewer
- **Status:** In Progress
- **Milestone:** [Milestone 4: TUI & UX Enhancements](/docs/project/milestones/04-tui-ux-enhancements.md)
- **Depends On:** [04-05-context-metadata](./04-05-context-metadata.md)
- **Specs:** [Interactive Session Workflow](/docs/project/specs/interactive-session-workflow.md)
- **Prototype:** None
- **Component Docs:** [TextualPlanReviewer](/docs/architecture/adapters/inbound/textual_plan_reviewer.md), [IAgentCatalog](/docs/architecture/core/ports/outbound/agent_catalog.md), [LocalAgentCatalog](/docs/architecture/adapters/outbound/local_agent_catalog.md), [ISessionManager](/docs/architecture/core/ports/outbound/session_manager.md)
- **Scope Slug:** `context-actions`

## Goal
Make `e` do the obvious thing on every context node — open the session or turn manifest, open the file itself, or switch persona — so the key stops being silently dead on the panel a reviewer consults most, and so a persona switch re-composes the agent+MRP system prompt from there on exactly as `resume -a` does.

## Context
- `check_action_logic` (`src/teddy_executor/adapters/inbound/textual_plan_reviewer_logic.py`): Returns `False` for any node whose payload is neither `ActionData` nor `ContextItem`, which covers `CONTEXT_ROOT`, `SYSTEM_LABEL`, `SESSION_LABEL`, `TURN_LABEL`, and `HISTORY_LABEL`; for a `ContextItem` it allows only `toggle_selection` and navigation. `edit_details` is therefore disabled on every context node today.
- `ReviewerApp.action_edit_details`: Branches three ways — redirect to `view_details` for an executed action, delegate to the list-view editor when the right pane holds focus, and otherwise call `edit_action_logic`.
- `launch_editor(app, content, suffix=..., persistent_path=..., skip_confirm=True)` (`textual_plan_reviewer_editor.py`): Opens a real file in place and cleans up only temp files, which is exactly the seam `preview_readonly` already uses to show a READ resource without harvesting edits.
- `app.plan.plan_path`: Names the on-disk `plan.md`; its parent directory is the current turn directory that owns `turn.context`. `app.project_context.session_root` names the session directory that owns `session.context`.
- Personas: `PromptManager` resolves a persona only from `.teddy/prompts/`, which `teddy init prompts` populates by copying the six bundled prompt files; there is no bundled fallback at resolution time. `list_prompt_names()` in `src/teddy_executor/prompts.py` already scans that directory for stems, so the roster adapter delegates to it rather than reimplementing discovery. A workspace may therefore legitimately carry a reduced, extended, or empty roster.
- `canonical_agent_name` (`src/teddy_executor/core/utils/string.py`): Already normalizes persona names case-insensitively, so the roster and the selection must present canonical names.
- **Switch semantics (product decision, 2026-11-26):** picking a persona on the System node behaves like `resume -a` — the agent plus MRP system prompt is re-composed from that point on. `PromptManager.compose_system_prompt(agent_name)` (`prompt_manager.py:206`) is that composition and `fetch_system_prompt(agent_name, turn_path)` (`:157-171`) is what the planner calls, so the switch changes the name the next turn is planned with rather than editing a prompt file or a config value. The current turn keeps its already-composed plan, which is why the effect is visible from the next turn's header and trace.
- **Session-root prompts win:** `fetch_system_prompt` returns an existing `<session>/<agent>.md` verbatim and never re-composes it, so a customized session prompt keeps governing that persona even after a switch. That is correct — the customization is deliberate — but the slice must state it, because it is the one case where a newly selected persona's workspace prompt does not take effect.
- **Persistence:** `ISessionManager.set_session_agent(session_name, agent_name)` (`session_service.py:559`) already writes `meta["agent_name"]`, the same field `resume -a` sets and `_echo_config_success` reads (`session_cli_handlers.py:1524`), so the switch writes that field instead of adding a second one.
- **Model row coupling:** the effective model resolves flag, then `agents.<persona>.model`, then `llm.model`, so after a switch the Model row added by [04-05](./04-05-context-metadata.md) must be re-resolved through the overlay; otherwise the panel keeps naming the previous persona's model while a different one answers. That coupling is why this slice lands after 04-05 rather than beside it.
- `docs/project/specs/interactive-session-workflow.md`, Context Node Interactions: Fixes the first two behaviours — `e` on the Session or Turn root opens the corresponding `.context` file, and `e` on a file path node opens that file.

## Scenarios

> As a reviewer, I want to read the session manifest without leaving the TUI.

```gherkin
Given a context panel whose session root is .teddy/sessions/20260124-add-user-auth
When I press e on the Session label
Then .teddy/sessions/20260124-add-user-auth/session.context opens in my editor
```

> As a reviewer, I want to inspect a context file the plan will read.

```gherkin
Given a context panel listing docs/project/PROJECT.md
When I press e on that file row
Then docs/project/PROJECT.md opens in my editor
And no confirm prompt is shown
```

> As a reviewer, I want to switch persona from the panel and have it take effect.

```gherkin
Given a context panel whose System node shows Pathfinder
When I press e on the System node and select Developer
Then the session records Developer as its agent
And the next turn is planned with the Developer persona and the shared protocol re-composed
And the Model row shows the model resolved for Developer rather than for Pathfinder
```

## Edge Cases
- **Missing manifest**: If the session root is set but `session.context` is absent, then the app notifies instead of opening an empty buffer, because a blank editor would misrepresent a missing file.
- **Unknown turn directory**: If `plan.plan_path` is `None` (a `--plan-content` run), then the Turn label notifies that the turn context is unavailable, because the reviewer must not guess a directory.
- **Pruned file**: If a `ContextItem` points at a path that no longer exists, then the app notifies with the path, because a context entry can outlive the file it names.
- **Toggle preserved**: If the user presses Enter or Space on a context item, then selection still toggles, because `e` must not absorb the toggle binding.
- **No session in scope**: If `project_context.session_root` is `None`, then the System node notifies that no session is in scope and the panel stays unchanged, because a persona switch persists into a session and must not invent one.
- **Missing handles**: If the app holds no agent catalog or no session manager, then the System node notifies that switching is unavailable instead of raising, because `ReviewerApp` is constructed across roughly twenty-five call sites and an absent optional handle must not crash the reviewer.
- **Empty roster**: If `.teddy/prompts/` holds no prompt file, then the modal is not opened and the app notifies that no personas are installed, because prompt resolution reads only `.teddy/prompts/` and never falls back to the bundled resources — offering a name the planner cannot load would be a false promise.
- **Dismissed switch**: If the agent modal is dismissed, then nothing changes and no metadata is written, because an abandoned selection must be inert.
- **Current persona marked**: If the roster opens, then the active persona is marked as current, because a menu that hides the present choice invites accidental re-selection.
- **Session-root prompt**: If the newly selected persona has a stored `<session>/<persona>.md`, then that stored prompt governs and only the header and Model row change, because `fetch_system_prompt` never re-composes a session prompt.
- **Model overlay absent**: If `agents.<persona>.model` is unset for the new persona, then the Model row falls back to `llm.model`, because the overlay merge leaves omitted keys on the global default.

## Key Unknowns
- None. The switch semantics are settled by the 2026-11-26 product decision, the roster seam (`list_prompt_names`) and the persistence primitive (`set_session_agent`) both already exist, and every branch above is drivable through the injected catalog fake.

## Implementation Notes
- **Orientation audit:** every claim in `Context` was verified against source. `action_edit_details` branches three ways, `check_action_logic` allow-lists a `ContextItem` to toggle and navigation only, the context tree attaches the five sentinels plus a `{"type": "SYSTEM_PROMPT"}` leaf for the persona row, and `test_reviewer_app_context_previews.py` asserts aggregate rendering rather than `e`, so no part of this slice is pre-delivered.
- **Port shape:** outbound ports are `@runtime_checkable` Protocols with `...` bodies and docstring contracts, so the interface test asserts the attribute, the signature, and `isinstance` against the protocol instead of expecting an instantiation failure.
- **Optional handles:** `ReviewerApp(` is constructed at roughly twenty-five sites (the wrapper, `TuiDriver`, and unit and acceptance tests), so the catalog and the session manager arrive as keyword arguments defaulting to `None`; the System node notifies rather than raising when either is absent.
- **Re-partition:** the original Adapter deliverable bundled two unrelated changes — the roster adapter and the selection modal — so the modal became its own Wiring deliverable drawn against the harness fake, and the real adapter followed with its own integration test.
- **Model re-resolution:** `resolve_effective_model` (`core/domain/models/config_schema.py`) is the reuse seam; the reviewer re-runs it for the newly selected persona rather than recomputing the flag/persona/global overlay.
- **Session identity:** `project_context.session_root` is `.teddy/sessions/<name>`, absolute when derived from a turn directory, so `Path(session_root).name` is the session name `set_session_agent` receives.
- **Persistence is the whole switch:** `set_session_agent` writes `meta["agent_name"]`, recomposes the agent+MRP prompt through `fetch_system_prompt`, and prunes the previous persona's session-root file, so the reviewer adds no composition logic of its own.
- **Read-only opens:** `launch_editor(..., persistent_path=<real file>, skip_confirm=True)` opens a file in place without harvesting, which is the seam both the manifest rows and the file rows use.
- **Delivered port:** `IAgentCatalog` promises one member, `list_agents() -> tuple[str, ...]`; canonicalisation, de-duplication, and stable ordering are stated as postconditions in the docstring and pinned by the adapter's own test rather than re-implemented in the protocol, which can only promise the member and its return type. `AgentCatalogError` carries no payload, because a roster failure needs no extra context to be actionable. The contract test asserts conformance in both directions, so a future double that renames the member is rejected at the boundary instead of failing inside the reviewer.
- **Delivered double:** `FakeAgentCatalog` (`tests/harness/setup/fake_agent_catalog.py`) holds a configurable roster, canonicalises each name through `canonical_agent_name`, and collapses duplicates through `dict.fromkeys` so the declared order survives first-appearance. Its default roster derives from `_PROMPT_FILES` in `core/services/init_service.py` — the in-source single source of truth the bundled copy and drift check already share — so the double cannot drift from the personas `teddy init prompts` installs. It never calls `list_prompt_names()`, which is a `.teddy/prompts/` disk scan and would make a hermetic unit test depend on workspace state. `list_calls` records the roster each listing answered, or `None` for a scripted failure, so a test can distinguish never-listed from listed-and-answered from listed-and-failed.
- **Registration seam:** the binding is `TestEnvironment.with_agent_catalog(catalog=None)`, mirroring the `with_real_*` shape, and registers the double as an `instance=` under `IAgentCatalog`. It is deliberately not an entry in `_register_default_mocks`: no harness fake lives there (they are hand-constructed and constructor-injected), and the composition root does not register `IAgentCatalog` at all until the `LocalAgentCatalog` Adapter deliverable lands. Binding the port from the harness is therefore the only way a reviewer test can obtain a roster today, and keeping it out of the mock defaults means the real adapter can later take that slot without the harness shadowing it.
- **Drivable roster failure:** the double can script an `AgentCatalogError`, which is what `LocalAgentCatalog` will raise on a listing failure. The slice's Edge Cases name an empty roster but not an unreadable one, so the consequence is recorded here for the modal deliverable: the persona modal must notify when listing fails instead of letting the error escape into the TUI, and this double makes that branch drivable without a real filesystem fault.

- **Delivered dispatch (`edit_details`):** `check_action_logic` gained `edit_details` in the `ContextItem` allow-list and a scope-header branch between the `ContextItem` and non-`ActionData` branches that admits `edit_details` on `SESSION_LABEL`/`TURN_LABEL` alone, so `SYSTEM_LABEL` still falls through to the rejection until the persona modal lands. `edit_action_logic` intercepts through the existing `_is_context_data` predicate before `handle_edit_action`, so neither a `ContextItem` nor a sentinel ever reaches action editing and no second copy of the sentinel list appears.
- **Collapsed-root trap (cost three turns, now pinned):** Textual 8.2.8's `Tree.move_cursor(node)` sets `cursor_line = node._line`, and an unrendered child carries `_line == -1`, so the cursor lands nowhere, `cursor_node` is `None`, and `check_action_logic` answers from its `if not node: return False` guard. That reads as a disabled binding rather than a navigation mistake, which is why five behavioural failures looked like a production defect while the gate was already correct. The reviewer builds the Context root collapsed (`helpers.py:180`), and the suite's own precedent expands first (`test_tui_section_boundaries.py:118`); the new module's `_park_cursor` helper therefore expands the root and asserts `cursor_node is node`, converting a silent mis-navigation into a loud failure.
- **Resolve-then-notify:** `open_context_node` resolves the target before delegating, so each failure branch emits exactly one notification and `launch_editor` owns the opening message. That ordering is what makes the missing-manifest assertion a single-element list rather than a two-element one. The handler deliberately never calls `find_editor()`: a spec-mock console tooling answers with a truthy non-string command, and `os.path.basename` would raise on it.
- **Read-only in place:** every branch routes through `launch_editor(app, "", persistent_path=<real file>, skip_confirm=True)`, the seam `preview_readonly` already uses. `is_temp` is `False` for a persistent path, so nothing is deleted, and the mock-editor hook writes into the real path — which is why the target file's new content is the honest observable for "opened at that path".
- **Refactor folded in:** the two duplicated existence checks collapsed into `_existing_path(app, target, subject)`, which owns the check, the notification, and the POSIX rendering. The subject is parameterised, so the three messages read "Context file not found", "Session manifest not found", and "Turn manifest not found" without three copies of the same branch. `ContextItem` moved to the module-level import block, and the function-local `Path` import disappeared in favour of the module's existing `pathlib`.
- **Coverage added:** the sixth case pins the slice's "Pruned file" edge case on the branch the refactor rewrote, asserting one notification naming the path and no file created — the branch and its assertion now change together instead of drifting apart.
- **Open boundary:** a `ContextItem` whose path is a URL still notifies "Context file not found". That is unchanged by this deliverable, so it is not a regression, but the spec never decides whether such a row should preview through `WebContentService` like a READ-on-URL does.
- **Delivered picker:** `AgentSelectScreen(agents, current)` is a `ModalScreen[str]` inserted beside the three existing modals, carrying `AGENT_CURRENT_MARKER = "(current)"`, pre-highlighting the active persona through `ListView.index`, canonicalising `current` through `canonical_agent_name`, and dismissing `None` on `escape` so an abandoned selection is inert. It dismisses through `on_list_view_selected`, which is what `enter` posts, so no extra binding contradicts the list's own navigation.
- **Push style, settled by probe not by reading:** a throwaway two-app probe showed `push_screen_wait` raising `NoActiveWorker: push_screen must be run from a worker when wait_for_dismiss is True` from a plain `action_*`, while `push_screen(..., callback=...)` delivered the picked value and returned the app to the main screen. The dispatch therefore pushes with a callback, and the probe also confirmed the `e`, `down`, `enter` sequence reaches the node and that `enter` posts `ListView.Selected`. The probe is scratchpad and is deleted at Delivery.
- **One predicate, two callers:** `is_system_node(data)` is now public in `logic.py` and `_is_context_data` delegates to it, so the System row and its persona leaf are recognised in one place; the dispatch branch in `open_context_node` and the `check_action_logic` branch both call it rather than re-deriving the dict shape. The System branch is placed after the absent-handle and session-scope checks, so no file target is ever resolved for a persona row.
- **Tracer-bullet scope:** the dismissal callback emits `Selected agent: <name>` and nothing more. Persisting the switch belongs to the Migration deliverable, which is why this deliverable proves the value crossing the boundary without claiming the effect — a notification that reads as a completed switch while writing no metadata would be the worse false promise.
- **Registry deliberately untouched:** `IAgentCatalog` is registered nowhere until the Adapter deliverable, so `registries/reviewer.py` still resolves neither handle. Production therefore reports "Agent switching is unavailable in this reviewer." — the honest state rather than a switch that cannot complete. `ISessionManager` is already container-registered (`container.py:310`), so Cleanup wires both at once.
- **Report ordering is a contract:** the opener checks absent handles, then session scope, then roster readability, then roster emptiness, each emitting exactly one message and never opening the modal. The tests pin each branch to a single-element notification list, so a future added check cannot silently double-report.
- **Corrected my own Red flaw:** Textual 8.2.8 exposes no `Label.renderable`, so the initial assertion would have failed on `AttributeError` and read as a production defect. The probe showed `.content` returns the plain string (`render()` wraps it in `Content(...)`), and the assertion now reads `.content`. The committed `test_reviewer_app_context_actions.py` expected `edit_details` to be `False` on `SYSTEM_LABEL`; enabling the row made that stale, so it flipped to `True` in the same change, docstrings included.
- **Escalation, not absorption:** `launch_editor` awaits `push_screen_wait(ConfirmScreen())` from `action_edit_details` when the app is not headless — the exact shape the probe proved raises `NoActiveWorker`. Every existing test masks it behind the `headless` short-circuit, so the shipped confirm flow is plausibly broken at a real terminal. This is outside the slice and belongs to the Debugger with its own case file.

- **Delivered adapter:** `LocalAgentCatalog` (`src/teddy_executor/adapters/outbound/local_agent_catalog.py`) takes one injected zero-argument lister and holds no concrete discovery mechanism. Production supplies `list_prompt_names`, a test supplies the same real scanner bound to an isolated workspace, so neither the adapter nor its test imports a second discovery path. The `__init__` parameter deliberately carries no default: DI purity forbids a concrete dependency hiding behind one, and the composition root is the only place that knows which scanner to inject.
- **The injection was forced by the scanner's shape, not chosen for taste:** `list_prompt_names()` takes no arguments and resolves `.teddy/prompts/` by walking upward from `Path.cwd()`, so an unparameterised adapter would make its own integration test mutate the process working directory with no seam to exercise. Binding the callable instead keeps the test real — the production scanner over a temporary tree — while the adapter stays ignorant of where the roster lives.
- **Postconditions collapse into one expression:** `dict.fromkeys(canonical_agent_name(name) for name in names)` yields order preservation, canonicalisation, and first-appearance deduplication together. It is the same expression `FakeAgentCatalog` uses, so the double cannot be kinder than production and a reviewer test cannot pass on a behaviour the real adapter would not honour.
- **Error translation mirrors the PDF precedent:** `PypdfExtractor` chains one specific library error into `PdfExtractionError(message, source=...)` via `from`, and this adapter chains `OSError` into `AgentCatalogError(f"Failed to list agent personas: {error}")` the same way. It carries no payload because the port's `Raises` clause promises only the condition, and a roster failure needs no extra field to be actionable.
- **Hermeticity was verified against the harness, not assumed:** `monkeypatch.chdir(tmp_path)` already appears in seven integration tests, the only hook mentioning `chdir` *requires* it before a raw `cli.invoke` rather than banning it, and `make test` runs bare `uv run pytest` with no `--basetemp` override, so `tmp_path` lands outside the repository and the upward walk cannot discover the project's own prompts. An "empty roster" case that silently found `.teddy/prompts/` in the checkout would have been a test that could never pass honestly.
- **The duplicate case is written as one stem under two extensions:** `pathfinder.md` plus `pathfinder.xml` proves deduplication on every OS in the matrix, whereas `Pathfinder.md` plus `pathfinder.md` would collide into one file on macOS's case-insensitive filesystem and prove nothing there. The case therefore also documents the real scenario it guards — a stale `.xml` persona left beside its Markdown replacement, which is exactly what `prefer_markdown` resolves elsewhere.
- **Red was genuine, so the six assertions are not vacuous:** collection failed with `ModuleNotFoundError` on the adapter module while `AgentCatalogError`, `IAgentCatalog`, and `list_prompt_names` all imported successfully, which isolates the absence to the module under construction rather than to a wrong import surface.
- **Registration stayed out of this deliverable:** the adapter is bound neither in `container.py` nor in `registries/reviewer.py`, so production continues to report "Agent switching is unavailable in this reviewer." That is the honest state — a catalog the registry cannot reach yet — and Cleanup wires both handles at once, including the `list_prompt_names` argument at the composition root.

- **Delivered switch:** `_apply_agent_selection` derives the session name from `Path(context.session_root).name`, persists through `set_session_agent`, assigns `agent_name` and the re-resolved `model_name` on the non-frozen `ProjectContext`, repaints both surfaces, and reports `Switched agent to <Name>` once. `set_session_agent` already canonicalises, writes `meta["agent_name"]`, recomposes the session-root prompt, and prunes stale siblings, so the reviewer composes nothing and the "next plan names the new persona" proof is that boundary call plus the existing `test_set_session_agent_persists_recomposed_prompt_at_session_root`.
- **Two repaint targets, deliberately:** the detail pane is re-rendered for `tree.cursor_node.data` rather than a hardcoded `SYSTEM_LABEL`, because `e` is admitted on the persona leaf as well as the System row, so a leaf-initiated switch would otherwise leave the aggregate pane showing the previous persona. The leaf is repainted by the new `refresh_system_node`, which syncs the leaf's own payload from `project_context` before refreshing — the pane renders from that same dict, so a stale `agent` there would contradict the label directly above it.
- **Label single-sourced:** `format_system_prompt_label(agent_name, tokens)` and `SYSTEM_PROMPT_LEAF_TYPE` live in `helpers.py` and serve mount time, `refresh_node_logic`'s new persona-leaf branch, and `populate_context_detail`'s type check, so a switch cannot leave the label shaped differently from how the tree was built. The mount-time `token_str` intermediate was deleted in the same edit because it became an unused assignment, which `ruff check --fix` rejects in the pre-commit hook.
- **Predicate, not a third literal:** `is_persona_leaf(data)` recognises the dict payload and `is_system_node` delegates to it, so `check_action_logic`, `_is_context_data`, and the refresh all agree without another copy of the shape. The import direction is safe and was verified, not assumed: `logic.py` imports `helpers` at module level while `helpers` reaches into `logic` only inside function bodies.
- **Model re-resolution mirrors the CLI banner:** `resolve_agent_llm_overrides(config.get_setting("agents", {}), agent)` then `resolve_effective_model(None, overlay.get("model"), config.get_setting("llm.model", ""))`, reporting `Unknown` when nothing resolves, so a switch with no config in reach never keeps the previous persona's model. The `--model` flag keeps its recorded limitation: the reviewer holds no reader for `meta["model_override"]`, so the flag slot stays empty and a flagged run keeps the flag at the provider while the row names the persona's model.
- **Guard costs nothing, prevents a swallowed traceback:** `_apply_agent_selection` skips persistence when the session manager is absent or the session is unscoped, even though `_open_agent_selector` already verified both. A Textual message-loop callback swallows an `AttributeError` rather than surfacing it, so the cheap check is what keeps a future caller's mistake loud.
- **Stated, not "fixed":** a stored `<session>/<persona>.md` keeps governing that persona after a switch, because `fetch_system_prompt` returns it verbatim and never re-composes it.
- **Harness:** `TuiDriver` gained a `config_service` pass-through (it already forwarded the other two handles), and the switch module gained a bound `_config(agents, llm_model)` double plus `_detail_map(app)` reading `DetailItem.data["key"]/["val"]` from the mounted pane — the observer shape `test_textual_plan_reviewer_helpers.py` established, reused rather than reinvented.
- **Process cost, recorded rather than hidden:** the Red was clean and the Green took two turns, but reaching them took nine discovery turns and one validation abort, the abort caused by writing a FIND block against a `_driver` signature reconstructed from memory (`agent_catalog`/`session_manager` instead of `catalog`/`session_manager`). The leaf label nearly drifted the same way — its rendered form is `'  Pathfinder 4.0k'` from a two-part f-string — so the expression was read rather than re-derived. Reading four lines costs one turn; guessing them cost several.
- **Lint gate, waived inline rather than in config:** the first commit attempt was refused by `PLR0913` on `_driver`'s six arguments, with every other hook green.
