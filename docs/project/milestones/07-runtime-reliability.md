# Milestone: Runtime Reliability & Boundary Purity

- **Status:** Planned
- **Depends On:** None
- **Specs:** None. Every requirement fixes a defect with an observable failure mode; none changes a specified format.

## Motivation
Remove the reliability defects and layering violations that the consolidation program does not own: make session metadata survive a hard kill, make the suite's flakes and latency budgets deterministic, bound the two heuristics that can silently degrade a run, collapse the resume state machine to one source of truth, and take the adapter libraries out of `core`. Each item was previously a numbered debt entry with no owning slice.

## Requirements
1. **Durable `meta.yaml` writes** — `SessionRepository.save_meta` writes through `IFileSystemManager.write_file` (`Path.write_text`), so a hard kill mid-write leaves a truncated file that `load_meta` either reads as `{}` — erasing the cumulative cost and usage ledger — or raises a `ParserError` out of `teddy resume`. Land an atomic temp-file-and-rename write plus a tolerant load for the truncation window. Owner: [07-01](/docs/project/slices/07-01-durable-session-metadata.md).
2. **Deterministic suite** — three known non-determinisms: a CWD leak under `pytest-xdist` in `test_file_system_adapter_recursion.py`; a sibling test in `test_planning_service_logging.py` that passes only through retry exhaustion; and a preflight acceptance test that failed once in ~2200 runs because it reads ambient stdin/stderr state. Each gets a named remedy — a CWD-snapshot fixture, a single-generation `get_completion` double, and an injected preflight double. Owner: [07-02](/docs/project/slices/07-02-test-suite-integrity.md).
3. **Honest latency budgets** — `test_context_service_performance.py` and `test_tree_generator_performance.py` assert wall-clock budgets from `perf_counter()`, so xdist contention inflates them exactly as it inflated the validator budget already repaired. The remedy is per test rather than uniform: thread CPU time where the work is CPU-bound, and a filesystem call-count budget where it is I/O-bound, because thread time on an I/O-bound path measures nothing and would make the assertion vacuous. Decide explicitly whether the `GITHUB_ACTIONS` skipif stays, because as written CI never guards either regression. Owner: [07-02](/docs/project/slices/07-02-test-suite-integrity.md).
4. **Bounded exhaustive matcher tier** — when no FIND line anchors verbatim, `gather_candidate_starts` seeds a window at every line start and `_evaluate_candidates` runs a full `SequenceMatcher` ratio per window, measured at 462 / 912 / 1827 ms on 400 / 800 / 1600-line files. Bound the work behind a configured cap that is far above any realistic pool, and report truncation explicitly rather than returning a silent best-effort answer. Owner: [07-03](/docs/project/slices/07-03-bounded-edit-matcher.md).
5. **Symmetric matcher ambiguity guard** — `EditSimulator._apply_single_edit` evaluates ambiguity before the threshold check and is correct only because the matcher now gates `is_ambiguous` on the effective threshold. Add the matching `and score >= threshold` guard so the defence does not rest on one caller. Owner: [07-03](/docs/project/slices/07-03-bounded-edit-matcher.md).
6. **Interactive-prompt sentinel hardening** — `ShellAdapter._detect_interactive_prompt` fires on a non-zero exit whose output incidentally contains a prompt-like substring, so a full `make test` run can have its entire stream replaced and its real result hidden. Require a genuine TTY or stdin signal plus a quiet tail rather than a bare substring match, and preserve the captured output when the sentinel does fire. Owner: [07-04](/docs/project/slices/07-04-interactive-prompt-sentinel.md).
7. **Resume state machine single source of truth** — `awaiting_reply` has exactly one writer (`session_orchestrator.py:367`, reached only through `_is_pipeline_message_stop`, which returns `False` when `not pipeline`) and one reader (`_should_consume_awaiting_reply`, `session_lifecycle_manager.py:320-322`), whose body ORs the flag with `plan.is_communication_turn()` and whose own docstring states that an interactively-interrupted communication turn "lacks the flag but is semantically awaiting a reply". Record the state wherever a communication turn stops and collapse the inference to one branch, so plan shape stops being a resume input. Owner: [07-05](/docs/project/slices/07-05-resume-state-truth.md).
8. **Non-communication pending-plan reply semantics (verified delivered — preserve)** — measured as already delivered by `0d5928cf`, `c4c4ae74` and `0e52b212`: the pending branch seeds `plan.metadata["user_request"] = message` (`session_lifecycle_manager.py:126-134`), an unparseable plan gets the reply appended by `_record_reply_on_resumed_turn` (`:142`, `:324-349`), and a marked hard-killed turn recovers through `_recover_interrupted_turn` (`:491-521`), pinned by `test_session_lifecycle_pending_plan_non_communication_resume.py`. The as-built rule is forward-into-execution, so the residual work is a regression test owned by the slice that rewrites the same branch. Owner: [07-05](/docs/project/slices/07-05-resume-state-truth.md).
9. **Core boundary purity** — six adapter-library imports sit inside `core`: `yaml` in `init_service.py`, `prompt_manager.py`, `session_lifecycle_manager.py`, and `session_repository.py`; `typer` in `session_orchestrator.py` and `core/utils/terminal.py`. Name the structured-document concern once as a codec port and move console presentation and termination out of core, because the core-isolation law and the boundary hook disagree today. Owner: [07-06](/docs/project/slices/07-06-core-boundary-purity.md).
10. **Report rendering consolidation** — merge the two `## Resource Contents` render sites in `execution_report.md.j2` into the single classification pass, and extend `tests/harness/observers/report_parser.py` to extract inline fenced content blocks so observers stop needing raw-regex fallbacks. Owner: [07-07](/docs/project/slices/07-07-report-rendering-consolidation.md).
11. **Contract-faithful port doubles** — `test_session_manager_contract.py` enumerates `ISessionManager`'s members by hand, so every additive Protocol member breaks it manually, whereas a check that derives the member set from the Protocol tolerates additions. Replace the hand-written enumeration or document the convention that makes additions safe. The same infidelity runs the other way: a port double leaves a capability boolean unset (`ILlmClient.supports_pricing` is the measured case), so a truthy mock default silently stands in for a product premise the moment a gate that short-circuited on it is removed — slice 04-05 hit exactly this when dropping a shadow `context_window > 0` conjunct turned an unstated `supports_pricing` into a fabricated zero. Give the doubles explicit defaults that state what is unsupported, and record the convention. Owner: [07-02](/docs/project/slices/07-02-test-suite-integrity.md).
12. **Editor seam injection** — six reads of `TEDDY_TEST_MOCK_EDITOR_OUTPUT` sit inside two production adapters: `textual_plan_reviewer_editor.py:240` (`handle_mock_diff`), `:280-281` and `:400` (`launch_editor`, `handle_mock_editor`), and `console_interactor.py:68` and `:114` (`prompt_for_message`, `_launch_editor_synchronous`). Inject an editor-launch port at the composition root so the harness substitutes a double instead of an environment variable, because a production adapter branching on test-only state is boundary impurity regardless of age, and the `None`-versus-empty distinction and the availability-before-temp-file ordering must survive the move. Land a structural hook that fails on any `TEDDY_TEST_*` read under `src/`, because the grep that proves today's removal is a one-time check while the next adapter can reintroduce the same seam. Owner: [07-08](/docs/project/slices/07-08-editor-seam-injection.md).
13. **Collectible harness fixtures and bound mock doubles** — two harness defects surfaced while closing the CI flake recorded in [04-litellm-call-count-leak](/docs/project/debugging/04-litellm-call-count-leak.md). `guard_os_killpg` in `tests/harness/setup/composition.py` is an `autouse=True` fixture that pytest never collects, because fixtures register only from conftest files and plugin modules, so the `os.killpg` protection its docstring promises is not in force; it moves the way `reset_shared_litellm_double_per_test` did, into `tests/conftest.py`. `test_validation_then_retry_wiring` builds `Mock(spec=IConfigService)` directly instead of the designated mock-registration helper, which is the prohibition the mock-binding rule states verbatim, and leaves an exhausted list `side_effect` behind for whichever test runs next; bind it through the helper. Land the structural check that makes the first defect impossible to reintroduce, failing on any `@pytest.fixture` carrying `autouse=True` outside a conftest or plugin module. Owner: [07-02](/docs/project/slices/07-02-test-suite-integrity.md).

## Constraints
- **Sequencing with the CI flip:** Requirement 9 becomes build-breaking the moment [05-04](/docs/project/slices/05-04-ci-gate-split.md) makes the `static-analysis` job blocking, because `check-architecture-boundaries.py` fails on these six sites today while running non-blocking. Requirements 1 through 8 may land in any order; Requirement 9 must land before or with that flip.
- **`meta.yaml` atomicity precedes any marker field:** do not fold the `execution.started` marker into `meta.yaml` until Requirement 1 lands, because the marker sits inside the one artifact a hard kill actually corrupts and its failure mode points the wrong way.
- **YAML line-editor excluded:** the bespoke comment-preserving line editor in `YamlConfigAdapter.set_setting` stays out of scope until either `ruamel.yaml` is accepted as a dependency or config mutation grows beyond the current keys. This milestone records the decision point and does not perform it.
- **No behaviour change beyond the defect:** Requirement 7 changes a state machine, so it lands with a test that drives both stop paths, because the current inference is what makes the bug untestable, and it keeps the delivered pending-reply behaviour (Requirement 8) pinned rather than re-litigated.
- **Heuristic bounds are measured:** Requirements 4 and 6 both narrow a heuristic or a detection rule, so each records its before-and-after measurement in `## Implementation Notes` rather than asserting an improvement.
- **Poka-Yoke:** Requirement 3's decision about the CI skipif is recorded, not deferred, because a budget that CI never runs is documentation dressed as a test. Requirement 1's atomic write path and Requirement 9's boundary are both enforced by structural checks rather than prose.
