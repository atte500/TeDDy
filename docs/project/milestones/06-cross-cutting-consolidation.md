# Milestone: Cross-Cutting Consolidation

- **Status:** Planned
- **Depends On:** None
- **Specs:** None. Every requirement preserves an existing format or fixes a boundary; the one documented exception is stated under Constraints.

## Motivation
Give every concept that currently lives in more than one place one authoritative definition — production literals and helpers, exception types, harness doubles, and the action-type registration surface — so a change lands once instead of four times, and finish the two bounded sweeps that the duplication allowed to persist: silent-error transparency and boundary translation.

## Requirements
1. **Single-source Production Literals & Helpers** — one definition each for the `cl100k_base` encoding name, the `TEDDY_LLM_API_KEY` env-var name, the `"disabled"` editor sentinel, the "Editor is disabled in config" message, the `## User Request` heading (with the preservation regex derived from it rather than restated), the `awaiting_reply` key, and the four duplicated helpers (API-key requirement, MESSAGE detection, preservation-arm decision, TUI diff routing), plus `InitService.__CONFIG_FILES`-style manifest symmetry and the unused `edit.similarity_threshold` branch. The session artifact filenames are the measured worst case: in `src`, `plan.md` is spelled in 12 modules, `meta.yaml` in 10, `report.md` / `turn.context` / `session.context` in 8 each, the sessions root in 4, and `.web_cache.json` in 1. Owner: [06-01](/docs/project/slices/06-01-literal-helper-single-sourcing.md).
2. **Align `## User Request` Rendering** — both producers emit a bare fence matching `## User Reply`, the template path stops rstripping inside a fence, and the sanitizer compares fence width instead of testing a stripped prefix. Owner: [06-07](/docs/project/slices/06-07-user-request-render-alignment.md).
3. **Provider Resolution behind `ILlmClient`** — one operation returning a domain value object, so the preflight check and the API-key requirement check cannot disagree. Follows [05-08](/docs/project/slices/05-08-litellm-probe-seam.md), which migrates the six patching modules onto the adapter seam first. Owner: [06-02](/docs/project/slices/06-02-provider-resolution-port.md).
4. **Extract Shared Test Fakes** — three dict-backed `InMemoryFileSystem` fakes (`test_session_repository_meta_contract.py`, `test_session_service_turn_meta.py`, `test_session_lifecycle_resume_message_persistence.py`), four `termios` fakes, ask-loop editor/tooling fakes across three suites, the duplicated `mkdtemp` + `rmtree` lifecycle, the duplicated MRP resource-root setup, the duplicated `ISystemEnvironment` double (`_env()` in `test_session_loop_guard.py`, `_environment()` in `test_session_loop_baseline_reset.py` — escalated from slice 04-04, where a Cleanup deliverable could not add the harness test that a new shared factory would require), and the three contract-violating session containers whose `check_drift()` returns a dynamic mock with no `__len__`. Owner: [06-03](/docs/project/slices/06-03-shared-harness-doubles.md).
5. **Consolidate the Inbound-Port Contract Directory** — thirteen contract modules already live under `tests/suites/unit/core/ports/`; `test_run_plan_use_case_contract.py` sits alone at `tests/suites/unit/ports/inbound/`, so this is a `git mv` plus import fixes with proven collection parity. Owner: [06-03](/docs/project/slices/06-03-shared-harness-doubles.md).
6. **Failure-Transparency Sweep** — narrow or log the measured broad-catch inventory: 51 `except Exception` sites across 16 files, concentrated in `textual_plan_reviewer_editor.py` (7) and `update_checker.py`, `session_orchestrator.py`, `session_cli_handlers.py`, `cli_helpers.py` (5 each). Seven of the twelve modules this requirement once named carry zero broad catches. Zero broad catches is not the same as clean: `OpenRouterMetadataHydrator.__fetch_models` catches narrowly and returns an empty catalog with no log line, which is the sharpest gap in the sweep, and `session_replanner.py` swallows with a `nosec B112` and a `continue`. Owner: [06-04](/docs/project/slices/06-04-failure-transparency-sweep.md).
7. **Establish the `TeddyError` Root** — re-parent `ConfigurationError`, `FileAlreadyExistsError`, `MultipleMatchesFoundError`, `SearchTextNotFoundError`, `WebSearchError`, `InvalidPlanError`, `LlmApiError`, and `PlanValidationError` under the existing root, and standardize the inconsistent bases so a caller's `except OSError` or `except ValueError` stops silently catching a domain rejection. Owner: [06-05](/docs/project/slices/06-05-domain-exception-hierarchy.md).
8. **Specialize Domain Exceptions for Overloaded `ValueError`s** — 21 bare built-in raises in `src`, of which 11 sit in `session_repository.py`; introduce `SessionNotFoundError`, `SessionAlreadyExistsError`, `InvalidSessionPathError`, `WorkingDirectoryEscapeError`, and `UnknownActionError`. Owner: [06-05](/docs/project/slices/06-05-domain-exception-hierarchy.md).
9. **Reconcile Validation Error Naming** — disambiguate `InvalidPlanError` (parse-time), `PlanValidationError` (semantic pre-flight), and the `ValidationError` report DTO, which is not an exception at all and becomes `ValidationFinding` with every template, parser, and assertion updated. Owner: [06-05](/docs/project/slices/06-05-domain-exception-hierarchy.md).
10. **Translate the `WebScrapeError` Boundary** — wrap the `trafilatura` and HTTP/socket failures that currently escape `IWebScraper.get_content`, and replace the silent empty-string returns so a blocked page is distinguishable from an empty one. Owner: [06-05](/docs/project/slices/06-05-domain-exception-hierarchy.md).
11. **Single-source the Action-Type Registration Table** — collapse the surface that `git grep ActionType` matches across eight files into one declaration binding enum member, protocol name, parser strategy, factory construction, validator rules, and report label. JC-11 / Milestone 5's matrix guards the migration and is deleted by it. Owner: [06-08](/docs/project/slices/06-08-action-registration-collapse.md).
12. **Migrate Project Tooling to `justfile` and `scripts/`** — replace the seven Makefile targets with described recipes delegating to tested Python helpers, move the commit, CI-watch, log-extraction, and probe logic into `scripts/tooling/`, bound each helper's output without cutting a block mid-way, and correct the run-registration wait that `ci-watch` and `probe` share through `RETRY_POLLS` (10) x `RETRY_SLEEP` (2) — about 20 seconds, short enough on this repository's push rate to expire before GitHub registered a run that existed, blocking the session with a false "no run registered" fail-safe. `make/ci.mk` already attributes failing job names from `gh run view --json jobs`, which is what lets the CI split edit only the workflow. Owner: [06-06](/docs/project/slices/06-06-tooling-migration.md).
13. **Document the `SessionLifecycleManager` Contract** — the class owns the presence-gated resume prompts, the pipeline pass-through across the COMPLETE_TURN delegation, and turn finalization, but has no component page and no Component Map row, so four consumer pages reference behaviour with nothing to link to. Owner: [06-07](/docs/project/slices/06-07-user-request-render-alignment.md).
14. **Remove the Dead `trigger_replan` Parameter** — `original_plan_content` lost its last consumer when the internal replan call stopped passing it, so the parameter and every call site supplying it are removed in one commit. Owner: [06-07](/docs/project/slices/06-07-user-request-render-alignment.md).

## Constraints
- **Test Harness Strategy:**
    - **Single-source proof:** for each extracted constant or helper, a test imports the canonical definition from both former consumer sites and asserts identity, so a re-duplication fails loudly.
    - **Shared-fake adoption:** migrate the bespoke fakes onto the shared harness doubles and delete the local copies; the full suite stays green.
    - **Directory consolidation:** move with `git mv` and prove an identical collected total before and after, because a directory move is the one refactor that can drop cases without failing.
    - **Sweep policy:** for each broad `except`, either narrow the caught type or add debug-level logging before swallowing; legitimate "safe to ignore" cases keep an explicit comment and a documented boundary exemption.
- **Poka-Yoke:** a shared harness fixture removes the incentive to declare a private double, and a structural hook removes the possibility — a private `class _InMemoryFileSystem` inside a test module passes every gate that exists today.
- **No New Behavior:** every change preserves existing runtime behaviour and passes the full suite. **Documented exception:** the bare-fence decision under Requirement 2 is an explicit product change requested on 2026-11-06, so it alters rendered report bytes and the assertions that pin them; every other item stays behaviour-preserving.
- **Structural enforcement lands with its rule:** each sweep that can be enforced statically — private test doubles, a broad catch that neither logs nor re-raises, a bare domain raise — ships a `manual`-stage hook registered in `.pre-commit-config.yaml` and wired into the structural-check step list, never a slice of prose alone.
- **Ordering and overlapping seams:** Requirement 3 follows [05-08](/docs/project/slices/05-08-litellm-probe-seam.md); Requirement 2 and 13 follow [06-01](/docs/project/slices/06-01-literal-helper-single-sourcing.md) because the heading must be single-sourced before its bytes change; Requirement 11 follows both [04-11](/docs/project/slices/04-11-move-delete-actions.md) and [05-06](/docs/project/slices/05-06-action-registration-matrix.md). Requirements 1, 2, 7, and 13 all edit `session_service.py` or the exception module, so a concurrent run needs a separate workspace and a rebase before merge.
