# Milestone: Quality Gate & Debt Reconciliation

- **Status:** Planned
- **Depends On:** None
- **Specs:** None. Every requirement is measurement, enforcement, or removal; the formats it guards are specified by [Report Format](/docs/project/specs/report-format.md) and [Plan Format](/docs/project/specs/plan-format.md), and neither changes here.

## Motivation
Drive every blocking quality gate green, replace the bypass policy's prose with a check that fails the build, split CI into a blocking static-analysis job and an advisory metrics job, and prune the test cases whose behaviour a lower tier already pins. The advisory job stays advisory (2026-11-26 product decision): its file-length cap rises from 300 to 500 lines and nothing in it gains a merge veto. No requirement changes runtime behaviour.

## Requirements
1. **Static Analysis Green in `src` and `tests`** — reconcile the measured red surface (ruff 44, mypy 115 across 26 files re-measured on 2026-11-26, bandit 29) so the blocking `static-analysis` job of Requirement 4 has something green to enforce, and re-derive the mypy baseline from the live run rather than from the recorded file list. Owner: [05-01](/docs/project/slices/05-01-static-analysis-green.md).
2. **Suppression Audit and Enforced Bypass Policy** — reconcile 49 inline `noqa` lines (`PLR0913` 30, `PLC0415` 10, `F401` 6, `F811` 1, `C901` 1), 10 `type: ignore` sites, and 15 `per-file-ignores` entries, so each becomes reasoned, converted, or deleted; add a structural hook that rejects a suppression lacking a rule code and a reason; and walk the commit history for past bypasses, recording what was found in the slice's Implementation Notes because a past bypass cannot be re-run as a test. This is where the `PLR0913` parameter-object work lands. Owner: [05-02](/docs/project/slices/05-02-suppression-audit.md).
3. **Redundant Test Pruning** — delete the acceptance cases whose behaviour a lower tier already pins, demote the cases whose real shape is integration, and fold the two modules that live outside `tests/suites/` into the canonical tree. The ratio gate that used to motivate this work is deleted (2026-11-26), so the goal is one case per behaviour rather than an ordering target. Counts as measured: acceptance 186, integration 164, unit 1912. A 2026-11-27 sweep during [04-11](/docs/project/slices/04-11-move-delete-actions.md) also found `tests/suites/unit/core/services/test_validator_create.py` carrying a duplicated docstring and a duplicated `mock_fs.path_exists.return_value = True` assignment inside a single test body; its history (`e27aebd9`, `0b750e33`) predates that slice, so the dead statements are reconciled here rather than in the slice that noticed them. Owner: [05-03](/docs/project/slices/05-03-redundant-test-pruning.md).
4. **CI Gate Split** — three jobs on the existing OS matrix: blocking `test-suite`, blocking `static-analysis` (mypy, ruff, detect-secrets, bandit, pip-audit, the structural hooks), and advisory `quality-metrics` (file length, duplication), each with `fail-fast: false` and a bash default shell so platform-conditional type errors cannot hide on one runner. Green first, then split, then flip the three `ARCHITECTURE.md` bullets. Owner: [05-04](/docs/project/slices/05-04-ci-gate-split.md).
5. **Dead Code and Stray Instrumentation** — remove `execute_valid_plan` (`adapters/inbound/cli_helpers.py:209`), its function-local `import sys`, and the `DEBUG CLI` stderr print it writes; the helper has no call site and no test reference, because the `execute` command resolves `IRunPlanUseCase` directly. Owner: [05-05](/docs/project/slices/05-05-dead-code-instrumentation.md).
6. **Action-Type Registration Matrix** — one parameterized test iterating every `ActionType` against the registration surface, guarding [04-11](/docs/project/slices/04-11-move-delete-actions.md)'s MOVE/DELETE delivery. Deliberately temporary: [06-08](/docs/project/slices/06-08-action-registration-collapse.md) collapses the surface and deletes this guard. Owner: [05-06](/docs/project/slices/05-06-action-registration-matrix.md).
7. **Assert Scope Rule** — reserve `assert` for contract positions and require an explicit `TeddyError` raise for untrusted plan input, then narrow the repository-wide `[tool.bandit] skips = ["B101"]` to the contract sites. The census found 21 `assert` statements, of which only `action_factory.py` and `plan.py` sit on the untrusted path, so the conversion is small and the hook keeps a narrow scope. Owner: [05-07](/docs/project/slices/05-07-assert-scope-rule.md).
8. **LiteLLM Probe Seam** — migrate the six modules carrying 24 function-scoped `monkeypatch.setattr` sites onto the adapter's injected provider seam, extend the shared fake so a scripted per-attempt failure is expressible, then ban module-level patching of third-party modules in the same pass as the migration and never before it. Owner: [05-08](/docs/project/slices/05-08-litellm-probe-seam.md).

## Constraints
- **Already delivered, explicitly out of scope:** the `--console` flag and its code paths (release `v0.1.16`; `test_console_mode_deprecation.py` asserts both flags absent; a repository-wide census finds zero `src` hits), and the `C901` parser refactor (`MarkdownPlanParser.parse` is already split; the one remaining `C901` suppression is the demo script). Both are recorded here so the next reader does not re-open them.
- **Detect-secrets is red; the earlier "measured clean" reading is stale:** the tool is pinned at `v1.5.0` with a `1.5.0` baseline, but a live `--all-files` run flags `scripts/demo/record_demo.sh:56` (Secret Keyword) — the `sk-fake` placeholder the demo writes into its throwaway config. The disposition is the inline `# pragma: allowlist secret` the tool itself advises, not removal of the demo seam, and it lands with 05-01 because Requirement 4's `static-analysis` job cannot be green while it is red.
- **Blocked upstream, documented residual:** `pip-audit` cannot go green until litellm lifts its Python 3.14 cap, so it stays a documented residual in the blocking `static-analysis` scope rather than a slice.
- **Over-cap modules are reported, not gated:** at the 500-line cap the advisory job still flags `session_cli_handlers.py` (1595), `session_lifecycle_manager.py` and `litellm_adapter.py` (824 each), `session_orchestrator.py` (705), `__main__.py` (670), `session_service.py` (636), `textual_plan_reviewer_editor.py` (606), and `context_service.py` (575), plus the largest test modules. No requirement splits them and no merge is blocked on them. The recorded path for the matcher is stale — the real modules are `core/services/validation_rules/edit_matcher.py` and `.../edit_matcher_heuristics.py`.
- **Bypass policy is enforced, not described:** the Quality-Gate Bypass Policy becomes a `manual`-stage hook in Requirement 2, so it stops being prose that decays.
- **The watcher must attribute non-blocking failures:** `ci-watch` currently reports a pre-existing failure inside an advisory job identically to a new one, which is why the CI split cannot be observed without manual run archaeology. That fix belongs to the tooling migration ([06-06](/docs/project/slices/06-06-tooling-migration.md)) and is not duplicated here.
- **The advisory job's red surface is measured, and all of it is inherited:** run `45845540723` (tip) and run `45844594985` (base `08b0fda2`) fail the identical seven `Quality Checks` steps — detect-secrets, ruff check, mypy, pip-audit, architecture boundaries, file length, jscpd — with 24 steps passing in both and an empty symmetric difference. Nothing between those two commits made a red step redder at step level, so Requirement 1 is the blocker for Requirement 4 rather than a triage question. Step-level inheritance is weaker than file-level innocence, so every slice still owes its own files a clean manual-stage run.
- **No local entry point for the manual-stage gates:** attributing the advisory failures meant naming hook ids by hand, and a slice can therefore pass every local gate while its own files fail `mypy`. Requirement 4 makes those checks blocking in CI, which closes the merge risk; a single local target that runs them stays unowned, so it is recorded rather than scheduled.
- **Debt disposition — owned by other milestones:** preservation-arm extraction ([06-01](/docs/project/slices/06-01-literal-helper-single-sourcing.md)); the three `InMemoryFileSystem` fakes, the hand-written `ISessionManager` double, private-collaborator access around `SessionPruningService`, and the TUI preview-test mock migration ([06-03](/docs/project/slices/06-03-shared-harness-doubles.md)); the two `SessionReplanner` / `SessionPruningService` swallows ([06-04](/docs/project/slices/06-04-failure-transparency-sweep.md)); the `SessionLifecycleManager` component page and the dead `trigger_replan` parameter ([06-07](/docs/project/slices/06-07-user-request-render-alignment.md)); the VCP POSIX-shell friction and the fix-safe sentinel ([06-06](/docs/project/slices/06-06-tooling-migration.md)); the action-registration collapse ([06-08](/docs/project/slices/06-08-action-registration-collapse.md)).
- **Debt disposition — deferred to [Milestone 7](/docs/project/milestones/07-runtime-reliability.md):** both `meta.yaml` write/read atomicity and the prohibition on folding the `execution.started` marker in before it lands; the order-dependent recursion flake, the retry-exhaustion sibling double, and the preflight stdin flake; the wall-clock latency budgets and their CI skipif; the exhaustive matcher tier's latency; the matcher's asymmetric ambiguity guard; the interactive-prompt sentinel's false positive; the resume state machine's two-factor inference (the non-communication `PENDING_PLAN` reply path is measured delivered and pinned by [07-05](/docs/project/slices/07-05-resume-state-truth.md) instead); the six `yaml`/`typer` imports inside `core`; the report-template render-site merge and the ReportParser inline extraction; and the hand-written contract double's autospec convention; and the `InterruptGuard` drain flag surviving its own bracket, because one memoized container keeps a single guard alive across in-process commands, so a drained run could carry `interrupted` into a later run (production is unaffected at one process per invocation).
- **Resolved and removed:** the unreachable pruning readers were deleted by an earlier slice, so no work remains.

- **Debt disposition — unowned, needs its own slice:** a structural hook asserting that every component doc under `docs/architecture/` declares a `Classification` matching the leaf directory its `Source` path implies. The 2026-11-26 backfill classified 82 docs by hand; without the check, the first new component doc reintroduces the gap. No requirement here owns it, so it is recorded rather than scheduled.
- **Debt disposition — unowned, needs its own slice:** a structural hook asserting that every component doc under `docs/architecture/` is linked from the Component Map. The four `core/utils/` pages (`io.md`, `message_renderer.md`, `paths.md`, `interrupt_guard.md`) were mapped by hand on 2026-11-26 after three of them had gone unmapped since they were written; the map stays hand-maintained, so the first new component doc reintroduces the gap. No requirement here owns it, so it is recorded rather than scheduled.
- **Debt disposition — unowned, needs its own slice:** the conflict-marker gate is inert during a rebase. `check-merge-conflict` returns zero unless a `MERGE_MSG` file exists in the git directory or `--assume-in-merge` is passed, and `git rebase --continue` creates `rebase-merge/` instead, so the one hook whose purpose is catching conflict markers never fires during the one operation that produces them. Measured 2026-11-26: rebase commit `13f6a6a7` landed carrying markers in [Milestone 7](/docs/project/milestones/07-runtime-reliability.md) because a resolver aborted before writing the file and the resolving block staged it anyway, and the markers were swept by hand two turns later. The remedy is one line — pass `--assume-in-merge` to the hook in `.pre-commit-config.yaml` — plus a proof that a staged marker-bearing file fails the hook while a rebase is in progress.
- **Debt disposition — unowned, needs its own slice:** the duplication gate cannot pass. `.github/workflows/ci.yml:206` runs `npx jscpd --min-tokens 25 --threshold 0`, and a zero threshold fails on any duplication at all, so a tree already carrying 11.13% duplication reports exit 1 on every run regardless of what a slice changed. Measured 2026-11-26 on `5407cd29`: 932 files, 768,209 tokens, 1,217 clones, 12,394 duplicated lines (11.13%); python contributes 1,153 of those clones and 10,644 of the duplicated lines, and because the ignore list covers only `**/.venv/**`, `**/ports/**`, `**/prompts/**`, and `**/spikes/**`, the test suites are inside that count. The step sits in the non-blocking quality job, so nothing unsafe ships; the defect is that a signal which cannot pass carries no information and dilutes the same quality job the `Money Rendering` enforcer reports into — the inert-gate family recorded above. The remedy is a decision rather than a command: narrow the scope, or ratchet the threshold from the measured baseline and lower it as slices land, which is the advisory-metrics stance this milestone already states. No requirement here owns it.
