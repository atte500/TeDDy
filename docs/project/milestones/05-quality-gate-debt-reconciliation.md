# Milestone: Quality Gate & Debt Reconciliation

- **Status:** Planned
- **Specs:** TBD

## Goal
To clean up the codebase by eliminating unnecessary quality bypasses, removing dead code and redundant tests, and fixing pre-existing quality gate violations that block pre-commit and CI. This ensures the quality gates can run cleanly and the codebase is maintainable.

## Requirements
1. **Fix Pre-existing C901 Complexity:** Refactored `MarkdownPlanParser.parse` into helper methods; `ruff check --select C901` passes.
2. **Audit Inline Quality Bypasses:** Remove unnecessary inline suppression comments (`# noqa`, `# type: ignore`) across `src/` and `tests/`.
3. **Remove Redundant Tests:** Audit acceptance and unit test overlap (including `teddy update` notification tests).
4. **Fix Pre-existing Mypy Errors:** Resolve confirmed type errors across `action_executor.py`, `console_interactor_ask_loop.py`, `session_cli_handlers.py`, and `session_lifecycle_manager.py`.
5. **Audit Quality Gate Bypasses in Git History:** Verify `--no-verify` commits in git log.
6. **Reconcile Failing Non-blocking Quality Checks:** Drive the 9 failing quality checks green (detect-secrets, hygiene, ruff, mypy, bandit/pip-audit, structural, test pyramid, file length, jscpd).
7. **Split CI Quality Job into Blocking Static Analysis Gate:** Implement 3-job CI architecture on OS matrix (`test-suite`, blocking `static-analysis`, advisory `quality-metrics`).
8. **Enforce `assert` Scope Rule:** Codify `assert` for contract positions only; require explicit `TeddyError` raise for untrusted plan input validation.
9. **Add Action-Type Registration Matrix Test:** Guard Milestone 4 MOVE/DELETE delivery across the 6 registration sites.
10. **Address Structural File-Length Debt:** Split files exceeding the 300-line gate (`session_orchestrator.py`, `yaml_config_adapter.py`, `edit_matcher.py`, `web_scraper_adapter.py`, `tests/conftest.py`, `config_schema.py`).
11. **Migrate LiteLLM Adapter Tests Off Global Module Patching:** Replace `monkeypatch.setattr` on the `litellm` module across 4 test modules with constructor-injected provider fakes, then add deterministic check banning module-level third-party patching.

- **CI gate split (templates landed, implementation pending):** the template set now prescribes three CI jobs, all on the same OS matrix — the blocking test suite, a blocking `static-analysis` job holding the deterministic diff-actionable checks (`mypy`, `ruff`, `detect-secrets`, `bandit`, `pip-audit`, the structural hooks), and an advisory `quality-metrics` job for the aggregate gates (test-pyramid ratios, 300-line file length, `jscpd`). The matrix is deliberate for static analysis: a single runner hides platform-conditional type errors, which is exactly the `kbhit`/`getwch` class already in the mypy baseline. Every matrix job sets `fail-fast: false` and a bash default shell so the Windows leg runs the same commands as the others. The live `.github/workflows/ci.yml` still runs the single non-blocking `quality-checks` job, and the live `docs/architecture/ARCHITECTURE.md` still names that job in its `CI Pipeline`, `Pre-commit Hooks`, and `Type Enforcement` bullets. The split is the closing step of the Quality Checks reconciliation: green first, then rename and re-scope, then flip the three live architecture bullets. The transition commit renames a job, so `make ci-watch` cannot match the new failing job name against its base run and reads "YOUR regression"; expect-red or pin `BASE=` when watching it.

- **`assert` scope rule (contract vs. input validation):** `[tool.bandit] skips = ["B101"]` disables bandit's assert check repository-wide, so nothing currently distinguishes a contract assertion — correctly strippable under `python -O` per the ARCHITECTURE Design-by-Contract law — from an input-validation assertion guarding LLM-supplied plan content, which would silently vanish under `-O`. The repository does not run under `-O` today, so the risk is latent. Codify the distinction as a structural rule: `assert` is reserved for contract positions (pre/post-conditions and invariants), and untrusted-input validation requires an explicit `raise` of a `TeddyError` subclass. Scope the `B101` skip to contract-assert sites rather than the whole repository.
- **Action-type registration matrix test:** Registering an action type requires parallel edits in six sites (the `ActionType` enum, the `MarkdownPlanParser` dispatch map, both `ActionFactory` maps, `registries/validators.py`, and the report template); omitting one either fails pre-flight with "Unknown action type" or renders an unlabelled log entry. Add one parameterized test iterating every `ActionType` against every registration point, so a forgotten site fails immediately. This guards Milestone 4's MOVE/DELETE delivery, which must edit all six sites twice. The guard is deliberately temporary: Milestone 6's "Single-source the action-type registration table" collapses the six sites into one declaration, and the test becomes redundant once that lands.
