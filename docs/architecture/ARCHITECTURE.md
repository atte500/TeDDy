# System Architecture: TeDDy

This document outlines the technical standards, conventions, and setup process for the `TeDDy` project.

## Architectural Standards

- **Version Control:** Default to Trunk-Based Development on main. Commits MUST follow Conventional Commits. `make commit` is LOCAL-ONLY (stage, pre-commit auto-fix pass, commit); the push is deferred to the session Conclusion via `make push`, which rebases, pushes, then reports CI results back, blocking only on failures the push introduced.
- **Run Environment:** All execution commands MUST be prefixed with the project's designated runner ('uv run').
- **Failure Transparency:** Silent error suppression is strictly forbidden. Generic catch-all blocks MUST NOT be used to swallow errors. Every try/catch block MUST either catch a specific error type or ensure generic catches log full context and re-raise. Empty catch blocks are only allowed with an explicit "safe to ignore" comment.
- **Custom Exceptions:** All custom domain and boundary exceptions MUST inherit from `TeddyError` (`src/teddy_executor/core/domain/models/exceptions.py`). Raising bare `Exception`, `ValueError`, or `RuntimeError` for domain-level rejections or boundary translations is strictly forbidden. The CLI and top-level orchestrators catch `TeddyError` to report user-facing failures, allowing unexpected programming defects (`AttributeError`, `IndexError`, contract assertion failures) to fail-fast with complete diagnostic traces.
- **Testing Strategy:** Scope each suite by the boundary it crosses — Unit for isolated core logic, Integration for adapters and stateful fakes, Acceptance for outer-boundary journeys — and mandate designated temporary directories for detritus (`tests/.tmp/`). The Test Harness is a first-class boundary requiring its own unit tests. Mandate: Real domain objects for logic; In-Memory Fakes for state-managing Outbound Ports; Mocks ONLY for un-verifiable external side-effects. To prevent Mock Poisoning, any allowed Mocks MUST strictly bind to their target contracts (e.g., via the project's designated mock registration helper that enforces auto-speccing) to prevent Signature Drift. Direct instantiation of bare, dynamic mock objects is strictly forbidden. Global/runtime module patching is strictly forbidden to prevent State Leakage; swap dependencies explicitly via Constructor Injection. Ensure the suite is designed to be fast and parallelized. A session-scoped, autouse fixture (`_assert_no_test_pollution`) snapshots `git status --porcelain` before the suite and asserts no filesystem pollution after all tests complete, acting as a Poka-Yoke against stray test artifacts.
- **Dependency Injection:** Mandate strict Constructor Injection for all core domain services. All dependencies MUST be passed explicitly via constructors. Defaulting to null or dynamic resolution via a global or passed container is strictly forbidden. Core domain logic MUST NOT import or depend on external Dependency Injection frameworks or containers.
- **Deterministic Boundary & Anti-Pattern Enforcement:** Architectural layer boundaries (Core isolation from outer layers and adapter libraries), `spikes/` isolation, and banned test doubles (`mock.patch`, bare `MagicMock`) MUST be enforced via deterministic linter rules or CI `manual`-stage structural hooks rather than relying solely on prose documentation.
- **Centralized Configuration:** Hardcoded "magic numbers" or scattered fallback values for application logic are strictly forbidden. All configurable parameters MUST be centralized in the project's designated configuration layer (e.g., `IConfigService`). (Documented exception: the interrupt-feedback knobs introduced by Bug 58 — `InterruptGuard.GRACE_WINDOW_SECONDS` and `ShellAdapter._POLL_INTERVAL_SECONDS` — are intentional module-level code constants per an explicit 2026-10-03 product decision, not config-layer settings. The interruptible-wait wake slice `interruptible_call._POLL_SECONDS` follows the same treatment, as do the waiting indicator's `SPINNER_FRAMES` and `SPINNER_REFRESH_PER_SECOND`, which describe presentation frames rather than configurable behaviour.)
- **CI Pipeline:** Define two parallel jobs: 1) Blocking OS matrix test suite. 2) Non-blocking (continue-on-error: true) quality checks running fast formatters, linters, security/secret scanners, type checkers, and repository-wide structural checks (excluding sandboxes and third-party dependencies). The blocking test job MUST carry a wall-clock cap. The per-test CI budget MUST come from one shared test-harness constant, because the thread timeout method terminates an xdist worker outright.
- **Pre-commit Hooks:** Local pre-commit MUST stay fast: scoped strictly to staged files and limited to fast auto-fixers (`ruff check --fix`, `ruff format`, whitespace/EOF fixers), `detect-secrets`, and `check-merge-conflict`. The heavier checks — static type-checking (`mypy`), security scanning (`bandit`, `pip-audit`), the automated DI boundary verifier (ensuring core domain logic has zero external DI container imports), the rules to ban bare mock objects, and the repository-wide structural checkers — are scoped to the non-default `manual` stage and run explicitly in CI's non-blocking quality job.
- **Post-commit Execution:** The full test suite runs in a post-commit hook as an unskippable safety net. The hook is defined in `.pre-commit-config.yaml` with `stages: [post-commit]`. The hook script lives at `.githooks/post-commit.py` (cross-platform Python). If tests fail, the commit is automatically reverted via `git reset --soft HEAD~1`, keeping changes staged for investigation. This ensures `--no-verify` cannot bypass the test gate. The hook MUST first skip automated git operations (`rebase-merge`, `rebase-apply`, `MERGE_HEAD`, `CHERRY_PICK_HEAD`) so that `git pull --rebase` cannot silently drop replayed commits.

- **Experimental Code:** The `spikes/` directory is for rapid, isolated experimentation (including `debug/`, `prototypes/`, and `showcases/`) and is explicitly excluded from all quality gates (linting, types, complexity).

## Ubiquitous Language

The canonical domain vocabulary for TeDDy. All documentation, component names, tests, and agent prompts must use these terms consistently.

- **Session:** A stateful, multi-turn collaboration sequence between a user and an agent persona, persisted under `.teddy/sessions/<name>/`.
- **Turn:** A single discrete plan-execute cycle inside a session, identified by a zero-padded directory number containing `input.md`, `plan.md`, and `report.md`.
- **Agent Persona:** A specialized system prompt guiding a distinct phase of the software delivery lifecycle (Pathfinder, Architect, Prototyper, Developer, Debugger, Assistant).
- **Plan:** An immutable Markdown artifact (`plan.md`) generated by an agent, containing a structured rationale and either an action plan or a message.
- **Execution Report:** An immutable record (`report.md`) detailing the factual outcome, action logs, and any validation errors of a turn's execution.
- **Context Payload (`input.md`):** The complete forward-looking worldview assembled by `teddy context` for an upcoming turn. Its sections are ordered for provider prefix caching: the byte-stable `## System Information`, the session's own `## Session Resources` and `## Session History`, then the per-turn `## Git Status`, `## Project Structure`, and `## Resource Contents`, closing with the volatile `## Runtime` rows. Every byte ahead of the newest history entry is identical between two consecutive payloads.
- **Session Context (`session.context`):** The persistent set of file paths included across every turn in a session, seeded initially from `init.context`.
- **Turn Context (`turn.context`):** The dynamic working set of file paths scoped strictly to the current turn, updated forward-looking by `READ` actions.
- **Session Root:** The directory of the session a context payload is assembled for (`.teddy/sessions/<name>/`). Every `get_context` caller running inside a session supplies it, and it gates the session-mode payload shape: a session-scoped path that is the session's own history renders under `## Session History`, a session-scoped path that is not renders under `## Session Resources`, and every turn-scoped path renders under `## Resource Contents`. A file read from another session is a resource, not our own history. `None` means no session is in scope: the hoist is skipped, neither session section renders, and every resource renders under `## Resource Contents`.
- **Action:** A single atomic operation within a plan (`CREATE`, `EDIT`, `EXECUTE`, `READ`, `RESEARCH`, `MOVE`, `DELETE`).
- **Execution Sequence:** The `int` an action records when the orchestrator loop or the reviewer resolves it — dispatched or skipped, never at parse. It is the one ordering key behind both the console log and `report.md`, and a hand-executed action keeps the number it recorded, so a partly hand-executed plan reports the order its actions actually ran.
- **Communicating Turn:** A turn that outputs a `## Message` instead of an `## Action Plan`, used for approval gates, user questions, or handoffs.
- **Plan Approval (`require_approval`):** Whether the plan is reviewed before its actions run. Derived from `--yolo`, `yolo_default`, and `--pipeline`, resolved once at startup and threaded down as the `require_approval` flag. When set, the TUI plan reviewer presents the whole plan for one batch review; actions are selected, edited, or deselected there, and no per-action prompt follows. The flag once carried the name `interactive`, which read like presence while meaning approval. It answers "may this run act without asking?", never "is someone there to answer?".
- **User Presence:** Whether a human can answer a prompt right now. Derived from `ISystemEnvironment.isatty()` (a terminal is attached to stdin) and `--pipeline` (a pipeline run never prompts). It answers "is someone there to answer?", never "may this run act without asking?".
- **Prompt:** A request for user input inside a run — the startup setup questions, the blank `-m` prompt on resume, the awaiting-reply reply. Every prompt MUST gate on User Presence, never on Plan Approval, because the two signals are independent: a yolo run at a terminal has presence and no approval, a pipeline run has neither. Gating a prompt on approval is why `teddy resume -m ""` once resumed with no prompt under `yolo_default: true`.
- **Candidate:** A window of consecutive file lines seeded by the matcher's heuristic tiers and scored against a FIND block; the ambiguity count is the number of refined candidates at or above the similarity threshold.
- **Token Usage:** The provider's own per-completion accounting for a turn — its input `prompt_tokens` and the portion it served from its prompt cache (`cached_tokens`) — persisted as integers in `meta.yaml` beside the running `cumulative_*` pair the Session Cost line derives its cache ratio from. Distinct from `token_count`, the client's pre-call request estimate that drives the context-budget check.
- **Web Content Cache:** The session-scoped, URL-keyed store of fetched remote bodies at `<session_root>/.web_cache.json`, holding only successful fetches as the untruncated text. An absent entry means "not fetched yet", never "fetch failed".
- **Web Content Service:** The core coordinator every remote fetch passes through. It consults the cache, fetches on a miss, stores the verbatim body, and caps only the value a caller asked to have capped.
- **Auto-Pruning:** The ordered heuristics that deselect session-context items so the turn context stays bounded: validation-failure pruning, then the retention ceiling, then the global Turn-scope budget. `auto_pruning.enabled: false` disables the chain and returns the context unchanged.
- **Retention Ceiling:** `auto_pruning.max_turns_retention` bounds how many distinct turns the turn-scoped context may hold. Nothing is deselected at or below it; past it, only the newest `max(1, max_turns_retention - retention_batch + 1)` turns survive, never fewer than one, and `auto_pruning.retention_batch` is how many of the oldest turns drop together, so a batch of `1` reproduces the per-turn cadence.
- **Waiting Indicator:** The transient spinner line `IUserInteractor.begin_waiting` / `end_waiting` bracket around a model call: one line beneath the telemetry, erased on completion, and rendered only when a terminal is attached so redirected logs and CI transcripts stay newline-delimited.
- **Session Cost:** The one recorded-money answer for a session. `resolve_session_cost` decides it from the turn's own `meta.yaml` — the recorded-cost signal or a priced model, never `cumulative_cost > 0` — and `format_cost_usd` renders it on every surface at exactly four decimals, with `$???` for an unrecorded figure, so the panel, the terminal telemetry line, and the guardrail notice cannot disagree. A recorded free-provider `0.0` and an unmeasured `None` are different facts and never render alike.
- **Model Identity:** The `(name, provider)` pair the reviewer displays. `ProjectContext.model_name` carries the effective model the composition root resolved, and `split_model_identity` derives the provider from its leading `/` segment because a LiteLLM provider prefix is optional, so a provider-less model reports `unknown` and an unresolved one `Unknown`.

## Component Map

This section serves as both the strategic **Boundary Map** and the detailed **Component Map** for the system.

**Boundary Analysis:** The `teddy_executor` follows a Hexagonal Architecture. The boundary separates the core business logic (domain models, services, and ports) from the platform-specific integration layer (the CLI) and infrastructure (the local filesystem, shell, and web). **Primary Adapters** act as the explicit translation layer across this boundary, ensuring the core remains isolated and independently testable.

## Key Architectural Decisions

This section serves as the "System Law" (Poka-Yoke) for TeDDy. It defines the prescriptive standards that all development work MUST follow.

- **Test Harness:** Reside exclusively in `tests/`. (Ensures strict isolation between production and test code.)
- **Temp Files:** Use `tempfile.mkdtemp()` (system temp directory) for test workspace directories. (Prevents filesystem pollution and avoids space-in-path failures when the project directory contains spaces.)
- **Global Config:** Unify in `tests/conftest.py` exporting from `tests/harness/setup/composition.py`. (Maintains a clean Primary Driving Adapter layer.)
- **Architecture:** Use Hexagonal Architecture (Ports & Adapters). (Enables independent testing and technology swapping.)
- **DI Implementation:** Use the `punq` library. (Decouples services from concrete implementations.)
- **DI Testing:** All tests requiring DI MUST use the centralized `container` fixture. (Ensures isolation and correct patching.)
- **DI Scopes:** Use `punq.Scope.transient` for services and adapters. (Prevents state leakage across CLI turns or tests.)
- **Acceptance Testing:** Use `typer.testing.CliRunner` for in-process execution. (Ensures speed, reliability, and mock respect.)
- **Terminal & Environmental Gates:** `typer.testing.CliRunner` captures stdout and stderr via non-TTY streams, so `isatty()` and `Console.is_terminal` default to `False` in acceptance tests. Any adapter or service gating behavior on terminal state or ambient environment MUST accept an explicit injected capability (such as `Console(force_terminal=...)` or `ISystemEnvironment`) at the composition root, and tests MUST exercise both terminal (`force_terminal=True` or a PTY) and non-terminal (`force_terminal=False`) branches rather than relying on `CliRunner` defaults. (Prevents TTY-gated branches from becoming unobservable in the test suite.)
- **Type Enforcement:** Rely on static checking (Mypy) in CI's non-blocking quality job; do not enforce at runtime. (Balances safety with low overhead.)
- **Structured Output:** Parse output into data structures before assertion. (Ensures resilience to minor formatting changes.)
- **CLI I/O:** Use positional arguments for files; reserve `stdin` for prompts. (Prevents input stream conflicts.)
- **Execution Testing:** Use `--plan-content` with `MarkdownPlanBuilder`. (Maintains protocol validity and test readability.)
- **Cross-Platform Path Assertions:** All tests performing path-based assertions MUST use the `POSIXPathMock.find_call_by_path(method, path)` helper. Manual inspection of `call_args_list` with `str()` comparisons is strictly forbidden as it breaks on Windows due to slash mismatches. Likewise, any mocked method's `side_effect` that matches on a path argument MUST compare through the shared `mocking.to_posix_path(value)` normalizer (e.g. `lambda name: resolved if to_posix_path(name) == to_posix_path(resolved) else None`); a raw `==` against an `os.path.expanduser`-derived baseline silently fails only on Windows because `POSIXPathMock` normalizes the argument BEFORE the side_effect runs. (Ensures CI stability across OS matrix.)
- **Execute Action:** Allow shell chaining and inline directives. (Simplifies protocol and maintains statelessness.)
- **Windows Failure:** Use `cmd /c` to isolate terminating commands. (Ensures parent process can report failures.)
- **Reporting:** Use Jinja2 Macros for modularity. (Ensures consistency and facilitates section extraction.)
- **Money Rendering:** Every displayed monetary amount MUST route through `format_cost_usd`, which renders the recorded amount at exactly four decimal places and an unrecorded amount as `$???`. Four decimals is the one standard on every surface: it is the precision the terminal Session Cost line already renders, it keeps the digits that distinguish two runs, and it absorbs float-accumulation noise (`1.2000000000000002`) below display precision, so the ledger stays the plain float total `meta.yaml` already stores instead of acquiring a second decimal representation. (Prevents the terminal telemetry line, the guardrail limit notice, and the reviewer's Context row from disagreeing about the same session cost.) Enforced deterministically by the `check-money-rendering` structural hook (`.githooks/check_money_rendering.py`, `manual` stage, run as its own step by CI's quality job), which fails on a hand-written dollar float format outside `money.py`; a second renderer is therefore a red build, not a review comment.
- **Encoding:** Explicitly specify `utf-8` for all file operations. (Ensures predictable platform-agnostic behavior.)
- **Serialization:** Enforce strict primitive validation before serialization. (Prevents infinite recursion or hangs from dynamic objects.)
- **Prompt Files Are Plaintext:** Agent prompt files (`src/teddy_executor/resources/config/prompts/*.md`) and the shared protocol base prompt (`src/teddy_executor/resources/MRP.md`) are LLM-facing plain text, NOT machine-parsed XML. They are assembled verbatim into the system prompt. (Rationale: no XML parser ever consumes these files, so XML-reserved characters MUST be written literally — e.g. `<type>` not `&lt;type&gt;`. Escaping adds noise, risks double-escaping, and obscures the text the model actually reads.)
- **DI Boundaries:** The `src/.../core/` directory MUST NOT import or depend on DI frameworks (e.g., `punq`). (Ensures Hexagonal isolation and prevents Service Locator anti-patterns.)
- **Constructor Injection:** All core services MUST use explicit constructor injection. (Mandates transparency and simplifies testing.)
- **Initialization:** Import heavy libraries (`litellm`, `trafilatura`) lazily. (Ensures CLI initializes under 500ms.)
- **Binary Stability:** Abstract heavy binary libs into private getters and mock the getter. (Prevents worker crashes in distributed tests.)
- **Performance:** Optimize core logic and plan validation for performance on large inputs to ensure low-latency feedback loops.
- **Pre-commit Workflow:** Scope local checks strictly to staged files. (Ensures fast feedback loops while delegating global checks to CI.)
- **Transient Resilience:** Outbound adapters for unreliable remote services (LLM, Web) MUST implement stateful retry logic (default 3 attempts) for known transient failure modes (SSL, Timeout, 5xx).
- **Web Content Cache:** Every remote fetch resolves through `WebContentService`, which owns the single cached-fetch workflow behind context assembly, a READ on a URL, and the reviewer's URL preview. It reads and merges the session-scoped `IWebContentCache` (`<session_root>/.web_cache.json`), a flat URL → untruncated body map. Only successful fetches are stored, so a failed URL leaves no entry and is retried on the next turn rather than rendering as permanently missing. A merge re-reads the on-disk map under one process-wide lock and replaces the file atomically, so concurrent fetches cannot drop each other's entry; missing, corrupt, or non-string-valued files read as empty. A `None` session root disables caching without creating a file. No TTL is applied; caching is intra-session only.

## Debug Diagnostics

- **Activation:** Use scoped environment toggles (e.g., `APP_DEBUG=auth,parser`).
- **Zero-Cost Guards:** All debug and prototype logic MUST use language-native dead-code elimination (e.g., `if __debug__:`) to ensure zero performance impact in production.
- **Branch by Abstraction:** All behavioral alternatives MUST be injected at the Composition Root via Constructor Injection. Mid-logic environment checks are strictly forbidden.
- **State Dumps:** Diagnostics should write transient state to `.tmp/debug/`.
